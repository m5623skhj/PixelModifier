# PixelModifier

투명 PNG 캐릭터 이미지에서 걷기·달리기 애니메이션 후보를 만들고, 선택한 결과를 PNG 스프라이트 시트로 저장하는 Windows 제작 도구입니다.

## 실행

Windows와 .NET 10 SDK가 필요합니다. 외부 NuGet 패키지나 온라인 생성 API는 사용하지 않습니다.

- `RunPixelModifier.bat` 실행
- 또는 `dotnet run --project src/PixelModifier.App -c Release`
- 이미지 경로를 실행 인자로 전달하면 시작할 때 불러옵니다.

## 사용 순서

1. **PNG 추가**로 투명 배경의 캐릭터 이미지를 1~N장 불러옵니다. 같은 캐릭터, 같은 시점의 이미지를 사용하세요.
2. 기준 이미지를 선택해 흰 관절 점을 실제 위치로 옮깁니다. A는 앞쪽, B는 뒤쪽 팔·다리입니다. 이미지는 투명 영역을 제외한 높이와 발 기준으로 자동 정렬됩니다.
3. **부위 표시**로 자동 추정을 확인합니다. 잘못된 경계는 **부위 칠하기**에서 고칩니다. 관절을 크게 옮겼다면 **부위 다시 추정** 후 필요한 부분을 칠하세요. 긴 코트는 **옷자락**으로 표시하면 다리와 함께 과하게 늘어나는 것을 줄일 수 있습니다.
4. 걷기 또는 달리기, 방향, 출력 프레임 수, 후보 수를 정해 **움직임 후보 생성**을 누릅니다.
5. 오른쪽 후보는 **동작 안정성** 점수가 높은 순서로 표시됩니다. 클릭해 크게 비교하고, 일시 정지와 프레임 슬라이더로 한 장씩 확인할 수 있습니다.
6. 셀 크기와 시트 열 수를 지정하고 **선택한 후보 PNG 저장**을 누릅니다. PNG 옆에 재생 정보 JSON도 저장됩니다.
7. **프로젝트 저장**으로 관절, 부위 경계, 기준 자세의 주기 위치와 생성 조건을 보관합니다. 원본 PNG 파일은 프로젝트와 함께 보관해야 합니다.

## 한 장과 여러 장 입력

- **한 장:** 지정한 관절과 부위 영역을 바탕으로 접지·발 떼기·이동·착지 단계와 골반, 무릎, 팔, 몸통 반동을 함께 계산합니다.
- **여러 장:** 각 이미지의 관절 자세를 주기 안에서 보간합니다. 사용자 기준 자세가 우선이며, 동작 규칙은 구간 사이에 작은 변화를 추가합니다.
- 처음에는 기준 이미지 N장을 주기 0%, 100/N%, …에 배치합니다. 두 장이면 0%와 50%입니다. 선택한 이미지의 **주기 위치**를 바꾸면 타이밍을 조절할 수 있습니다.
- 입력한 주기 위치는 가까운 출력 프레임으로 맞춥니다. 예를 들어 8프레임에서 33.3%는 네 번째 프레임(37.5%)에 해당합니다. 두 자세가 같은 출력 프레임에 놓이면 위치나 프레임 수를 조정해야 합니다.
- 걷기·달리기는 반복 동작이므로 마지막 기준 자세에서 첫 자세로 돌아오는 구간도 포함됩니다. 같은 시작 이미지를 100%에 다시 넣을 필요가 없습니다.
- 자세마다 관절을 확인해 주세요. 크기가 다른 PNG도 정렬되지만, 서로 다른 캐릭터나 시점은 자연스럽게 연결되지 않습니다.
- 색을 흐리게 섞는 전환을 사용하지 않습니다. 중간 자세로 이미지를 변형하고, 해당 시점과 가까운 기준 이미지에서 색을 가져옵니다. 기준 이미지의 실루엣이 크게 다르면 원본이 바뀌는 지점에서 형태가 튈 수 있습니다.

## 출력 규격

프레임은 왼쪽에서 오른쪽, 위에서 아래로 이어집니다. 모든 셀은 같은 크기이며 남는 셀은 투명합니다.

JSON에는 `frame_count`, `columns`, `rows`, `cell_width`, `cell_height`, `frame_seconds`, `anchor_x`, `anchor_y`, 후보 생성값과 `motion_quality` 평가값이 기록됩니다. 지면 기준점은 셀의 가로 50%, 세로 90%입니다. 움직임은 제자리에서 반복되며, 게임 내 이동 속도는 게임에서 처리합니다.

출력 프레임 수와 후보 수는 별도입니다. 예를 들어 **8프레임·12후보**를 생성하고 하나를 선택하면, 최종 PNG에는 선택한 후보의 8프레임만 들어갑니다.

## 품질과 자원 사용

동작 추론은 관절 길이와 접지 상태를 이용한 제약 계산으로 수행합니다. 걷기는 양발 지지 구간을 포함합니다. 달리기는 지면 밀기→뒤쪽 다리 접기→무릎 앞으로 들기→착지 준비의 전용 궤적과 양발이 뜨는 구간을 사용합니다. 한 장으로 생성하는 좌우 방향 달리기는 바라보는 방향으로 양쪽 무릎을 굽힙니다. 여러 기준 자세 사이의 보조 동작은 원본의 굽힘 방향을 유지합니다. 달리기의 기본 무릎 굽힘 한계는 120도이고, 원본이 더 굽혀져 있으면 그 자세를 허용합니다. 팔꿈치는 약 90도로 굽혀 앞뒤로 크게 흔듭니다. 발의 높이와 이동 속도는 구간 경계에서 부드럽게 연결합니다. 양발의 목표 위치에 맞춰 골반 높이를 계산하고, 두 다리가 동시에 닿을 수 없으면 보폭과 발 높이를 함께 줄입니다. 팔 흔들림은 이 보폭 제한과 독립적으로 계산합니다.

후보의 **동작 안정성** 점수는 접지 중 이동 오차, 관절 길이와 무릎 굽힘, 급격한 속도 변화, 마지막→첫 프레임 연결, 변형 제한에 따른 움직임 손실을 평가한 참고값입니다. 여러 기준 이미지는 사용자가 정한 자세가 우선이므로 미리 만든 접지 시간표로 발 미끄러짐을 평가하지 않습니다. 점수가 실제 그림의 미적 품질을 보장하지는 않습니다.

몸통·머리·옷자락과 팔다리의 위·아래 구간을 별도 레이어로 회전·합성합니다. 팔다리는 관절 회전을 그대로 반영하고, 옷자락의 추가 변형 제한은 옷자락에만 적용합니다. 부위별 제한량은 한 후보의 모든 출력 프레임에서 동일하게 유지합니다. 여러 기준 자세 사이의 보조 움직임도 기준 자세에 도달할 때 부드럽게 멈춥니다. 주기 전체의 자세 평가와 레이어 계산으로 후보 생성 시간과 메모리 사용은 늘어날 수 있습니다.

일반적인 2D 사람형 캐릭터의 팔다리를 기준으로 한 변형 도구입니다. 한 장의 픽셀 변형으로 가려진 부위나 새로운 방향의 그림을 복원할 수는 없습니다. 큰 보폭, 겹친 다리, 긴 옷에서는 변형이 어색할 수 있어 관절·부위 보정과 후보 비교가 필요합니다. 네발 캐릭터나 다른 골격은 별도의 동작 세트가 필요합니다.

원본의 보이는 픽셀은 부위 표시와 관절 위치에 따라 한 레이어에만 배정합니다. 팔다리가 몸통 앞뒤로 겹칠 수 있으며, 최근접 픽셀 샘플링과 알파 합성으로 그립니다. 팔꿈치나 무릎을 크게 굽힐 때 부위 경계에 틈이 보이거나 원본에서 가려졌던 부분이 드러날 수 있습니다. 관절 위치·부위 표시를 보정하거나 추가 기준 이미지를 사용하세요. 회전하거나 늘어난 도트의 모양은 달라질 수 있습니다.

미리보기는 메모리 예산에 맞춰 32~256px로 생성합니다. 저장 시 선택한 후보를 지정한 셀 크기로 다시 계산합니다. 현재 입력은 최대 64장, 후보는 1~64개, 출력은 2~240프레임이며 입력 장수보다 적은 프레임 수는 허용하지 않습니다. 셀은 32~4096px, 출력 시트는 최대 6,400만 픽셀입니다.

생성 중에는 입력 편집을 잠그고 복제한 관절·영역 설정을 작업 스레드에서 사용합니다. UI 이미지는 고정(Freeze)한 뒤 UI 스레드로 전달합니다.

## 개발 및 확인

```powershell
dotnet build PixelModifier.slnx -c Release
dotnet run --project checks -c Release
```

실제 PNG로 자동 추정 결과를 출력하려면:

```powershell
& .\src\PixelModifier.App\bin\Release\net10.0-windows\PixelModifier.exe --render-example "input.png" "outputs\example"
```

`src/PixelModifier.Core`는 픽셀, 관절, 동작, 변형과 프로젝트 저장을 담당하고, `src/PixelModifier.App`은 Windows UI와 PNG 입출력을 담당합니다. 새로운 동작은 동작 종류와 주기별 자세 계산을 추가하는 방식으로 확장합니다.
